## Key Topics — Hauptthemen

### 1. Software Quality Model — ISO/IEC 25010 Grundlagen

**🇬🇧** ISO/IEC 25010 defines a standardized framework for evaluating software product quality through 8 main quality characteristics:
**🇩🇪** ISO/IEC 25010 definiert einen standardisierten Rahmen zur Bewertung der Softwareproduktqualität anhand von 8 Haupt-Qualitätsmerkmalen:

| Quality Characteristic / Qualitätsmerkmal | Description / Beschreibung |
|---|---|
| **Functional Suitability / Funktionale Tauglichkeit** | Degree to which the functions meet stated and implied needs / Grad, in dem die Funktionen die Anforderungen erfüllen |
| **Performance Efficiency / Leistungseffizienz** | Performance relative to the amount of resources used / Leistung im Verhältnis zu den genutzten Ressourcen |
| **Compatibility / Kompatibilität** | Ability to share information or exchange data with other systems / Fähigkeit zum Datenaustausch mit anderen Systemen |
| **Usability / Benutzerfreundlichkeit** | Ease of use and learnability for the user / Einfachheit der Bedienung und Erlernbarkeit |
| **Reliability / Zuverlässigkeit** | System capability to maintain specified performance under specified conditions / Aufrechterhaltung der Funktion unter definierten Bedingungen |
| **Security / Sicherheit** | Degree to which data and information are protected / Schutzgrad von Daten und Informationen |
| **Maintainability / Wartbarkeit** | Ease with which software can be modified or improved / Leichtigkeit der Modifizierbarkeit und Verbesserung |
| **Portability / Übertragbarkeit** | Ease of transferring the software to another environment / Übertragbarkeit in eine andere Systemumgebung |

### 3. Deep Dive: The Analysis Phase — Analysephase in der Programmierung

**🇬🇧** Before writing a single line of code, the **Analysis Phase** ensures that customer requirements and technical boundaries are fully defined.
**🇩🇪** Bevor eine einzige Zeile Code geschrieben wird, stellt die **Analysephase** sicher, dass Kundenanforderungen und technische Rahmenbedingungen vollständig definiert sind.

| Phase Step / Schritt | Main Objective / Hauptziel |
|---|---|
| **Requirement Elicitation / Anforderungserhebung** | Gathering functional and non-functional requirements (IST-Zustand vs. SOLL-Zustand) / Erfassung funktionaler und nicht-funktionaler Anforderungen |
| **Feasibility Study / Machbarkeitsprüfung** | Evaluating technical, financial, and time constraints / Bewertung technischer, finanzieller und zeitlicher Rahmenbedingungen |
| **Specification / Spezifikation** | Documenting expectations clearly (e.g. Lastenheft / Pflichtenheft) / Klare Dokumentation der Erwartungen |

## Key Takeaway — Was ich gelernt habe

**🇬🇧**
- **Quality is multi-dimensional:** Software is not just "working code" — attributes like maintainability, security, and performance efficiency (ISO 25010) dictate long-term success.
- **Analysis prevents costly rework:** Diving straight into coding without a structured analysis phase leads to scope creep and architecture failures.

**🇩🇪**
- **Qualität ist multidimensional:** Software ist nicht nur „funktionierender Code" — Eigenschaften wie Wartbarkeit, Sicherheit und Leistungseffizienz (ISO 25010) entscheiden über den langfristigen Erfolg.
- **Analyse verhindert teure Nacharbeit:** Das direkte Programmieren ohne strukturierte Analysephase führt zu Scope Creep und Architekturfehlern.
